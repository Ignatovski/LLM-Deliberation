Rank-1 finding: CommandInjection (High). The form intended to accept an IP address executes additional shell commands chained via `;` (L003), and the response returns the output of `uname -a` (L004), directory listing (L005-L008), working directory `/app/vulnerabilities/exec` (L009), the executing user `www-data` (L010), and confirmation of container context via `/.dockerenv` (L011). This demonstrates unsanitized user input being passed to a shell interpreter — a textbook OS command injection. Severity is High because arbitrary command execution in the web server context allows enumeration, lateral discovery, and likely further exploitation, though execution is constrained to the `www-data` user inside a container, not root. The user_assumption is Wrong: while command execution is confirmed, L010 shows the process runs as `www-data`, not root, so the claim of "root-level access" is not supported by the evidence.
